## Критично — можно испортить данные

### 1. Ставку можно опустить ниже нуля

`place_bid` проверяет только относительные величины:

```sql
IF p_amount >= v_ride.current_price THEN ... END IF;
IF (v_ride.current_price - p_amount) < v_ride.bid_step THEN ... END IF;
```

Нижней границы нет. Для поездки типа `request` (запрос пассажира, водители сбивают
цену вниз) это значит: водитель вызывает RPC с `p_amount = -100000` — обе проверки
проходят, `current_price` становится отрицательным, ставка ложится в `bids`.
Ни `CHECK`, ни триггера, которые бы это поймали, в базе нет — проверено по
`pg_constraint` и `pg_trigger`.

Интерфейс сюда не пускает, но RPC вызывается напрямую по REST с обычным
пользовательским токеном.

**Лечится** проверкой `p_amount > 0` в `place_bid` плюс `CHECK (amount > 0)` на
`bids` и `CHECK (current_price > 0 AND start_price > 0)` на `rides`.

### 2. Вставка в `rides` идёт напрямую и не ограничена ничем, кроме длины текста

У `authenticated` есть INSERT на колонки `rides`, политика `rides_insert_auth`
проверяет только `auth.uid() = creator_id`. На числа ограничений нет вообще:

| колонка | что можно вставить сейчас |
|---|---|
| `seats` | 0, −5, 100000 |
| `start_price`, `current_price` | ноль и отрицательные |
| `bid_step` | 0 (тогда любая ставка проходит проверку шага) |
| `auction_hours` | до 32767 — `publish_ride_free` подставляет это значение в `now() + N hours` как есть, то есть аукцион на 3,7 года |

Форма создания поездки эти значения ограничивает (шаг от 10, цена > 0), но форма —
не защита.

## Заметно пользователю

### 3. Смена аватара не видна

`Profile.tsx`, `handleAvatarUpload`: путь `${profile.id}/avatar.${ext}` с `upsert: true`.
`compressImage` почти всегда отдаёт JPEG, значит путь постоянный — и `getPublicUrl`
возвращает тот же адрес, что и раньше. Файл в Storage заменился, `avatar_url` в базе
не изменился, браузер и CDN отдают закэшированную картинку. Человек грузит новое фото
и видит старое.

**Лечится** дописыванием версии к URL: `${publicUrl}?v=${Date.now()}`.

### 4. Профиль после сохранения показывает не то, что записано в базу

`handleSaveProfile` пишет в базу нормализованные значения, а в состояние — сырой ввод:

```ts
telegram: editData.telegram.replace(/@/g,'').trim() || null,   // → в базу
...
telegram: editData.telegram || null,                            // → в интерфейс
```

Ввели `@vasya` — на экране остаётся `@vasya`, в базе `vasya`. То же с `whatsapp` и
`max`, где в базу уходят только цифры. После перезагрузки значение «прыгает».

### 5. Ползунок скроллбара невидим

`src/index.css:144`:

```css
::-webkit-scrollbar-thumb { background: var(--color-surface-highest); }
```

Такой переменной в блоке `@theme` нет — есть `--color-surface-container-highest`
и `--color-surface-bright`. Значение невалидно, свойство отбрасывается, бегунок
прозрачный. Дорожка шириной 8 пикселей при этом нарисована. Видно во всех
браузерах на WebKit/Blink, то есть у подавляющего большинства.

### 6. Кнопка «Отменить поездку» может залипнуть навсегда

`TripDetail.tsx`, `handleCancelRide`: при успехе `setCancellingRide(false)` не
вызывается и `fetchRide()` не делается — расчёт на то, что придёт realtime-событие
об UPDATE. Соседние обработчики (`handleCloseAuction`, `handleCompleteTrip`) сделаны
иначе — с явным `await fetchRide()`. Если канал не подключился (free-тариф, лимит
200 соединений; в ленте и уведомлениях от realtime как раз отказались в пользу
опроса), кнопка остаётся в состоянии загрузки до перезагрузки страницы.

### 7. Быстрые кнопки ставки и поле ручного ввода противоречат друг другу

`TripDetail.tsx`: кнопки строятся как `bid_step × 1..4`, а поле требует
`minBidStep = Math.max(50, ride.bid_step)` и подписано «мин. 50 ₽».
При `bid_step = 10` (форма создания это разрешает) кнопка предлагает шаг 10 ₽,
поле такую же ставку не принимает, а база — принимает.

### 8. Двойной каркас страницы на `/my-trips` и `/ratings`

Обе страницы отрисовываются внутри `MainLayout`, где уже есть
`<main class="h-full overflow-y-auto md:pt-16">` и контейнер
`max-w-4xl mx-auto p-4 pb-32`. При этом каждая страница объявляет своё:
`min-h-screen`, собственную `fixed`-шапку и `pt-24 md:pt-32 pb-24`.

Следствия: контент гарантированно выше окна примерно на 150 пикселей даже когда
он пустой (прокрутка в никуда), отступы складываются вдвое, а `max-w-2xl` страницы
сидит внутри `max-w-4xl` layout'а — заявленная сетка не работает.

### 9. Поездку можно создать на уже прошедшее время

`CreateTrip.tsx`, `canGoNext` для шага 2 сравнивает только дату:
`parseISODate(formData.date) >= today`. Выбрав сегодняшнее число и время на два часа
назад, поездку можно опубликовать.

## Расхождения и мелочи

**10.** `public/manifest.json` — описание «Аукционный сервис поездок Сочи–Абхазия».
13.08 всё переименовали в «Россия ↔ Абхазия», манифест забыли.

**11.** `public/robots.txt` закрывает `/messages` и `/conversations` — разделов нет
с 10.08. При этом `/notifications`, `/payment`, `/receipt` не закрыты.

**12.** `finish_auction` при нулевых ставках ставит `status = 'cancelled'`, но не
заполняет `cancelled_at`. Лента показывает отменённые поездки сутки по условию
`cancelled_at >= вчера` — такие записи туда не попадают. В базе уже есть одна
такая из двух отменённых.

**13.** Часовой пояс базы — UTC, `departure_time` вводится по местному.
`auto_complete_expired_rides` считает `(departure_date + departure_time)::timestamptz`
как UTC и завершает поездки на три часа позже задуманного.

**14.** Черновики видны всем. Политика `rides_select_all` — `USING (true)`, у `anon`
есть SELECT. Чужой неопубликованный черновик читается по REST, а `/payment?ride=<чужой>`
показывает форму публикации (сама RPC чужого не пустит, но экран выглядит рабочим).

**15.** Гранты не дочищены. У `anon` и `authenticated` остались `TRUNCATE`, `DELETE`,
`TRIGGER`, `REFERENCES` на `rides`, `bids`, `users`, `reviews`, `notifications`.
DELETE перекрыт отсутствием политик, TRUNCATE через PostgREST недостижим — но это
мусор, который прошлые «hygiene»-миграции пропустили.

**16.** `rides_update_own` — мёртвая политика: у `authenticated` нет ни одного
UPDATE-гранта на колонки `rides` (и правильно — всё идёт через RPC).

**17.** Советники Supabase:
- `payments` — RLS включён, политик ноль (осознанно, доступ только у service_role, но линтер будет ругаться вечно);
- расширение `pg_net` установлено в схему `public`;
- в Auth выключена проверка паролей по базе утечек;
- 10 индексов ни разу не использованы.

**18.** Service worker: `CACHE_VERSION = 'apsny-shell-v1'` не меняется, `index.html`
кладётся в кэш один раз при install и больше не обновляется. После деплоя офлайновая
оболочка ссылается на хеши бандлов, которых уже нет.

**19.** Шрифты подключены через `@import url(fonts.googleapis.com)` первой строкой
`index.css` — поздний блокирующий запрос, `preconnect` к `fonts.gstatic.com` нет.

**20.** Линт: 39 предупреждений. Содержательных три — `setState` внутри эффекта
(`Profile.tsx:180`, `UserProfile.tsx:120`) и вызов `Date.now()` в теле рендера
(`TripDetail.tsx:186`). Остальное — `any` в блоках `catch`.

**21.** Стилей `:focus-visible` нет нигде. `.input-glass` гасит `outline` и рисует
своё кольцо, у кнопок и ссылок фокус остаётся браузерным по умолчанию.
