# Комплект для переезда на свой сервер

Файлы, которые пригодятся в день аренды сервера. Подготовлены заранее, чтобы
переезд занял вечер, а не неделю. Порядок работ описан в `MOVING_CHECKLIST.md`
в корне проекта — здесь лежит то, что в нём упоминается словами.

Сервер выбран по замерам из `НАГРУЗОЧНЫЙ-ТЕСТ-2026-08-13.md`: 4 ядра, 8 ГБ,
80 ГБ. Ограничение — память стека Supabase, а не процессор.

| Файл | Что делает | Когда применять |
|---|---|---|
| `docker-compose.override.yml` | Отключает analytics, vector и studio, ставит лимиты памяти контейнерам | Положить рядом с `docker-compose.yml` из репозитория supabase/supabase **до** первого запуска |
| `postgresql.tuning.conf` | Настройки PostgreSQL под 4 ядра / 8 ГБ | Подключить к конфигу базы до восстановления дампа |
| `nginx/apsny-transfer.conf` | Статика фронтенда и прокси к API со сжатием, TLS, заголовки безопасности и CSP | После получения сертификатов. **Заменить `<ДОМЕН>`** |
| `cron-jobs.sql` | Пересоздаёт 4 задачи pg_cron | Сразу после восстановления дампа |
| `backup.sh` | Дамп по расписанию **с проверкой восстановления** | Первым делом после переезда, до открытия доступа |
| `payments-enable.sql` | Отбирает право на публикацию мимо кассы | **Не сейчас.** Только в день подключения ЮMoney |

## Порядок

1. Сервер, домен, сертификаты.
2. `docker-compose.override.yml` рядом с официальным compose, поднять стек.
3. Настройки PostgreSQL, перезапуск базы.
4. Восстановить дамп, выполнить `cron-jobs.sql`.
5. **Настроить `backup.sh` и убедиться, что он проходит проверку восстановления.**
   Не откладывать: до этого момента данные существуют в одном экземпляре.
6. Конфиг nginx с заменённым доменом, проверить сжатие:
   `curl -s -H "Accept-Encoding: gzip" -o /dev/null -w '%{size_download}\n' https://api.<ДОМЕН>/rest/v1/rides?select=id&limit=50`
   Ответ должен быть в разы меньше, чем без заголовка.
7. Разделы A и B из `ПРОВЕРИТЬ.md` на новом сервере.
8. Платежи — отдельно и позже, см. `payments-enable.sql`.

## Чего здесь нет и почему

Секреты Vault, настройки Auth, bucket'ы Storage и сами файлы, Edge Function
вебхука — переносятся руками, список в `MOVING_CHECKLIST.md`, раздел 4.
Заранее их подготовить нельзя: они привязаны к новому JWT-секрету, который
появится только при первом запуске.
