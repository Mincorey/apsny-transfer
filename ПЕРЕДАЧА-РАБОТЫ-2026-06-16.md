## 1. Что за задача

Сайт apsny-transfer.vercel.app — аукционная площадка поездок Сочи ↔ Абхазия.
Берём 100 ₽ за публикацию поездки. Владелец — физлицо без самозанятости/ИП,
поэтому «белый» эквайринг недоступен. Решение: ЮMoney QuickPay (кошелёк) —
приём карт (вкл. МИР) и кошелька ЮMoney. СБП в кошельковом QuickPay нет.

Логика потока:
1. Пользователь жмёт «Оплатить и опубликовать — 100 ₽».
2. Поездка создаётся в таблице `rides`, но триггер БД `force_ride_draft`
   принудительно ставит ей `status='draft'` (черновик скрыт, в аукционе не участвует).
3. RPC `start_ride_payment(ride_id)` создаёт запись в таблице `payments` и
   возвращает уникальную метку `label`.
4. Браузер редиректит на ЮMoney QuickPay (сумма 100 ₽, метка = label).
5. После оплаты ЮMoney шлёт HTTP-уведомление на Edge Function `yoomoney-webhook`.
6. Функция проверяет подпись (HMAC-SHA256), сверяет сумму, вызывает RPC
   `publish_ride_paid` → поездка `draft → active`, таймер аукциона стартует от
   момента оплаты.

## 2. Архитектура (важно помнить)

- Стек: Vite + React 19 (SPA), Supabase (Postgres, обращение из браузера с anon-ключом),
  деплой на Vercel. Отдельного бэкенда нет — подтверждение оплаты делает Supabase
  Edge Function (серверная среда).
- Project-ref Supabase: `uprcnpgmmnvsoxasuhun`.
- Таблица поездок называется `rides` (НЕ trips). Статусы: draft / active / booked /
  completed / cancelled.
- Прямой UPDATE по `rides` запрещён RLS — все изменения через SECURITY DEFINER RPC.
- Webhook URL (вписывать в ЮMoney):
  https://uprcnpgmmnvsoxasuhun.functions.supabase.co/yoomoney-webhook
  ВНИМАНИЕ: НЕ apsny-transfer.vercel.app/api/... — на Vercel это SPA без бэкенда,
  тот адрес не работает (вернёт HTML, оплата не обработается).

## 4. ЧТО ДЕЛАТЬ ДАЛЬШЕ (go-live) — строго по порядку

Порядок важен: миграция ставит триггер, который ЛЮБУЮ новую поездку делает
черновиком. Если применить миграцию ДО выката нового фронтенда, поездки начнут
создаваться невидимыми. Поэтому сначала фронт, потом миграция.

ШАГ 1. Выкатить новый фронтенд.
  - Закоммитить и запушить изменения в GitHub (репозиторий Mincorey/apsny-transfer).
  - В Vercel: Project → Settings → Environment Variables добавить
    VITE_YOOMONEY_RECEIVER = 4100117652929755 (для Production).
  - Дождаться, пока Vercel пересоберёт и выкатит сайт.
  - Проверка: сайт открывается, поездки в ленте на месте (пока создаются как обычно —
    миграции ещё нет, и это нормально).

ШАГ 2. Применить миграцию к боевой БД.
  - Это сделает помощник (я) через подключение к Supabase — просто напиши
    «применяй миграцию». Либо вручную: Supabase Dashboard → SQL Editor → вставить
    содержимое supabase/migrations/20260616_yoomoney_payments.sql → Run.
  - После этого новые поездки создаются как черновики и публикуются только после оплаты.

ШАГ 3. Прописать секрет Edge Function.
  - Supabase Dashboard → Edge Functions → yoomoney-webhook → Secrets (Manage secrets).
  - Добавить: YOOMONEY_NOTIFICATION_SECRET = <секрет из ЮMoney>.
    (Секрет берётся в ЮMoney: yoomoney.ru/transfer/myservices/http-notification →
    «Показать секрет». В код/гит секрет НЕ класть — только в Secrets функции.)
  - SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY уже доступны функции автоматически.

ШАГ 4. Включить уведомления в ЮMoney.
  - Открыть: https://yoomoney.ru/transfer/myservices/http-notification
  - Поле «Куда отправлять (URL сайта)»:
    https://uprcnpgmmnvsoxasuhun.functions.supabase.co/yoomoney-webhook
  - Галочка «Отправлять HTTP-уведомления» — включена. Нажать «Готово».
  - Нажать «Протестировать»: должен прийти ответ 200 (после ШАГа 3 — пройдёт).
    Примечание: тестовое уведомление идёт без метки label — функция просто ответит 200.

ШАГ 5. Боевой тест.
  - Создать поездку → нажать «Оплатить и опубликовать — 100 ₽» → оплатить картой 100 ₽.
  - Проверить: в таблице payments строка стала 'paid'; поездка перешла draft → active
    и появилась в ленте; пользователя вернуло на /payment с сообщением об успехе.

## 6. Технические детали на память

- Сумма сверяется по полю withdraw_amount (сколько заплатил отправитель = 100 ₽).
  С карты ЮMoney удержит 3% комиссии с получателя → на кошелёк придёт ~97 ₽; это
  корректно, клиент заплатил 100 ₽. Комиссии: карта (AC) 3%, кошелёк (PC) 1%.
- Идемпотентность: повторное уведомление не публикует поездку дважды (проверка по
  статусу payments='paid' внутри RPC publish_ride_paid).
- Реквизиты кошелька (receiver): 4100117652929755.
- Документация ЮMoney:
  Форма: https://yoomoney.ru/docs/payment-buttons/using-api/forms
  Уведомления: https://yoomoney.ru/docs/payment-buttons/using-api/notifications
